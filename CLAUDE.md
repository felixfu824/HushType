# CLAUDE.md - HushType

> **Canonical agent context.** Claude reads this file directly. `AGENTS.md` is the cross-agent entry point and requires Codex and other agents to read this file completely before acting. Keep current architecture and release procedures here; keep transient task state in the Product/GtM workstreams.

Local-first voice-to-text for macOS + iOS. Qwen3-ASR on Apple Silicon via MLX, plus opt-in cloud dictation (OpenAI / Gemini, own-key direct) and opt-in cloud translated captions. Fully localized UI (English / zh-Hant-TW). MIT license.

## Build & Run

```bash
make install                    # Build macOS app → /Applications/HushType.app
make dmg                        # Build self-contained DMG (bundles OpenCC)
cd iOS && xcodegen generate     # Generate Xcode project for iOS
python3 scripts/ios_server.py   # Start experimental iOS server manually (or Settings > iOS)
```

Build outside OneDrive if `.build/` permissions fail: `swift build -c release --disable-sandbox --build-path /tmp/hushtype-build`

## Architecture (non-obvious decisions)

| Decision | Why | Reference |
|---|---|---|
| iPhone → Mac server, not on-device | iOS blocks Metal GPU in background; no CoreML port of Qwen3-ASR | `scripts/ios_server.py` |
| File-based IPC, not UserDefaults | UserDefaults cross-process broken with free provisioning | `iOS/Shared/AppGroupConstants.swift` |
| DispatchSourceTimer, not Timer | Timer needs main RunLoop; iOS doesn't spin it in background audio | `iOS/VoxKey/Services/BackgroundAudioManager.swift` |
| Audio engine always-on (orange dot) | Silence player kept process alive but timers didn't fire | `iOS/VoxKey/Services/AudioRecorder.swift` |
| NSAllowsArbitraryLoads only | NSExceptionDomains conflicts on iOS 26, both get ignored | `iOS/project.yml` → Info.plist |
| OpenCC server-side post-processing | Qwen3-ASR zh-TW output inconsistent; s2twp guarantees Taiwan vocab | `Sources/HushType/ChineseConverter.swift` |
| Bundled OpenCC in app bundle | DMG users have no Homebrew; app checks bundle first, falls back | `Makefile` → `bundle-opencc` target |
| Codesign with stable `--identifier` | Ad-hoc signed binaries get fresh cdhash on each build; TCC tracks by cdhash and silently revokes Accessibility permission every `make install`. Pinning the identifier keeps TCC tracking stable across rebuilds. **Caveat (observed repeatedly in practice): this only partially helps - with ad-hoc signing (no Team ID) macOS still falls back to cdhash for the designated requirement, so TCC grants (Accessibility, Microphone, Screen & System Audio) do NOT reliably survive rebuilds. Plan one permission-repair pass after every `make install`; minimize install cycles when testing.** | `Makefile` → `bundle` target |
| `xattr -cr HushType.app` before codesign when working inside OneDrive | OneDrive stores extended attributes (`com.apple.FinderInfo`, `com.microsoft.OneDrive.*`) on every file it syncs. `codesign --force --deep` refuses to sign any bundle that contains such xattrs, failing with `resource fork, Finder information, or similar detritus not allowed`. The failure happens silently inside `make install` because the preceding `bundle-opencc` step succeeds before the final bundle-sign step blows up, and the error is easy to miss in a long build log. Manually stripping xattrs before (or inside) `make install` avoids this. If you move the repo outside OneDrive the problem disappears; the fix is the workaround, not a code change. | `make install` troubleshooting |
| Interface language is an explicit next-launch preference | macOS Phase 1 ships English and Traditional Chinese (Taiwan) from app-owned `.lproj` resources. Settings > General offers Follow System / English / 繁體中文（台灣）. Choosing a different language only persists the next-launch preference and shows one compact confirmation; HushType never restarts, quits, or interrupts dictation/caption work on the user's behalf. Runtime lookup is requested locale → English → developer fallback, with explicit locale formatting and `.stringsdict` plural handling. | `Sources/HushType/Localization.swift`, `Sources/HushType/Settings/GeneralPane.swift`, `Sources/HushType/Resources/` |
| One unified seven-tab Settings window owns configuration | v0.5.11 replaced scattered submenus and two standalone settings windows with General, Dictation, Caption, Text, Cloud, iOS, and About tabs. Recovery paths deep-link to the relevant pane. Opening Settings activates HushType, orders the window front once, and reasserts on the next run loop so menu tracking cannot hide it; the window remains normal level, not always-on-top. | `Sources/HushType/Settings/SettingsWindowController.swift`, `Sources/HushType/StatusBarController.swift` |
| Onboarding runs BEFORE `CGEvent.tapCreate` | Kernel caches Accessibility permission per-process at first tapCreate call. If denied, the process can never see a subsequent grant - restart is mandatory. OnboardingManager catches the denial upfront and presents a Codex-like setup panel for Accessibility + Microphone. After Accessibility is granted, the panel offers an explicit restart path. | `Sources/HushType/OnboardingManager.swift`, `Sources/HushType/OnboardingSetupWindowController.swift` |
| Stale TCC reset is explicit, not automatic | HushType used to auto-run `tccutil reset Accessibility com.felix.hushtype` when Accessibility was missing. That fixed duplicate rows but was too magical. The v0.5.0 flow makes reset a visible `Reset Old HushType Entry` button with confirmation, for users who installed an older HushType, see duplicate entries, cannot find HushType, or have a broken switch. | `Sources/HushType/OnboardingManager.swift`, `Sources/HushType/OnboardingSetupWindowController.swift` |
| Permission drag helpers are non-modal utility panels | macOS sometimes requires users to manually add an app to a TCC list. The helper panel shows a draggable HushType app tile plus short instructions, while leaving System Settings interactive. It must not be blocked by `NSApp.runModal`; otherwise the close button and drag tile become unclickable. | `Sources/HushType/PermissionSettingsGuidePanel.swift`, `Sources/HushType/DraggableAppTileView.swift` |
| Screen & System Audio Recording permission is for audio; screen contents are not read | macOS groups system-audio capture under the Screen & System Audio Recording permission. HushType requests this for Live Caption from app/system audio, but only consumes audio buffers from ScreenCaptureKit. UI copy must stay trimmed and explicit: system audio is processed; screen contents are never read. | `Sources/HushType/SystemAudioPermissionFlow.swift`, `Sources/HushType/SystemAudioPermissionWindowController.swift`, `Resources/Info.plist` |
| AI Cleanup RETIRED (v0.5.5); dictation pipeline is fully deterministic | Text Polish superseded it as an explicit user action, so the automatic FM stage was removed end-to-end (−1,243 LOC). Dictation is now Qwen3-ASR → OpenCC → ITN → Dictionary → Punctuation with zero FM in the hot path - deterministic, no FM latency/hang risk per dictation. Text Polish (double-tap Right ⌥ / Services) is the only FoundationModels feature. | `Sources/HushType/TranscriptionEngine.swift`, PR #9 |
| Local and cloud dictation share one engine contract and post-processor | Local Qwen3, OpenAI, and Gemini conform to `TranscriptionEngine`. All successful text passes through `DictationPostProcessor` so OpenCC, ITN, dictionary, and punctuation behavior stays aligned. Cloud dictation requires the user's own key, explicit consent on the first cloud request of every app session, pre-upload duration/payload/cost checks, and direct provider requests with no HushType relay. Selecting a cloud engine can leave the local model unloaded, including on the next launch. | `Sources/HushType/TranscriptionEngine.swift`, `OpenAITranscribeEngine.swift`, `GeminiTranscribeEngine.swift`, `DictationPostProcessor.swift`, `CloudDictationOnboardingAlert.swift`, `CloudUsageTracker.swift` |
| Polish input wrapped in `<selection>...</selection>` before being passed to FoundationModels | Same structural prompt-injection defense as the old `<transcript>` wrap: selection content is data, never instructions - question-shaped selections get proofread, not answered. Every few-shot mirrors the wrap. The model deterministically echoes the tags for some inputs (trailing apostrophes) → output sanitizer strips them. | `Sources/HushType/PolishPrompt.swift`, `Sources/HushType/FoundationModelsPolisher.swift` |
| Polish overrides: `polish_rules.txt` (Settings-exposed, merged) + `polish_prompt.txt` (hidden, full replace) | Rules file is user-facing from Settings > Text > Polish instructions, with a template containing commented examples; the full-prompt file is the power-user/dev iteration path. Both hot-reload via the mtime-cached `CleanupPromptOverride` loader (kept after AI Cleanup retirement precisely for this). A rules edit changes the prompt fingerprint, which invalidates the prewarmed standby session. | `Sources/HushType/PolishPrompt.swift`, `Sources/HushType/CleanupPromptOverride.swift`, `Sources/HushType/Settings/TextPane.swift` |
| Text Polish keeps a prewarmed session pool of ONE | Measured 2026-07-22: the OS does NOT share instruction-prefix KV cache across `LanguageModelSession` instances, so a discarded warmup buys nothing. Keep one prewarmed standby, consume it for exactly one respond (statelessness preserved), replenish AFTER the respond returns - prewarm-before serializes the respond behind the prefill (+320 ms measured). Idle polish 688→400 ms; back-to-back degrades gracefully to baseline. | `Sources/HushType/FoundationModelsPolisher.swift` |
| Polish fails loudly; output guards revert bad model behavior | Opposite philosophy to the old silent AI Cleanup fallback: corrupted output (length drift, dominant-script flip, dropped language in a zh/EN mix, refusal text) shows an alert and leaves the selection untouched. Language guards get one retry with a keep-the-mix reminder. The model's persistent 妳→你/您 rewrite (resists prompting) is reverted deterministically via a diff-cluster check. | `Sources/HushType/TextPolisher.swift`, `Sources/HushType/PolishDiff.swift` |
| ASR model loads cache-first - zero network after first download | A live HF outage (resolve 503 with network up) bricked model load at launch: speech-swift always revalidated online, and HubApi auto-offline only covers no-connectivity. The forked speech-swift tries `HubApi(useOfflineMode: true).snapshot` first (disk-only validation: metadata + LFS hashes); online path only on first download / partial / corrupt cache. This also makes README's "之後完全離線" claim actually true. Dependency pinned by exact fork revision so upstream can't drift in unreviewed. | `felixfu824/speech-swift@d603472b` → `Sources/AudioCommon/HuggingFaceDownloader.swift`, `Package.swift` |
| Python path resolution for GUI apps | macOS GUI apps have stripped PATH; `/usr/bin/python3` != user's Python | `Sources/HushType/IOSServerManager.swift` |
| iOS Server is experimental, untested, and Settings-only | The long-stagnant Mac server is not a selling point and does not appear directly in the menu. Users must go to Settings > iOS, where copy states that it needs Python dependencies, uses port 8000, transcribes on the Mac with a local model, and cannot run alongside Live Caption because both compete for MLX/GPU resources. | `Sources/HushType/Settings/IOSServerPane.swift`, `Sources/HushType/IOSServerManager.swift`, `scripts/ios_server.py` |
| Right ⌥ dual-purpose: hold=record, tap=translate | Recording already has a <0.3s "too short" guard that discards short audio. Repurposed that branch to trigger translation instead of discarding - zero latency impact on the recording path, no changes to HotkeyManager needed. | `Sources/HushType/AppDelegate.swift` |
| MLX GPU cache cap is set at launch, not just in LiveCaptionManager | MLX's GPU buffer recycle pool (`MLX.Memory.cacheMemory`) is unbounded by default. `clearCache()` ran only on manual Unload and Live Caption stop, and `MLX.Memory.cacheLimit` was set only inside `LiveCaptionManager.start()` - so a **dictation-only** session (Live Caption never started) ran on MLX's unbounded default and `phys_footprint` climbed past 5 GB over a session (the Unload diagnostic reclaimed 5.2 GB instantly, confirming it was recyclable MLX GPU memory, not other processes). Fix (v0.5.2): set `MLX.Memory.cacheLimit = 1 GB` **once at launch** so the pool is bounded for every path; footprint plateaus ~1.7 GB. The cap limits only the *idle reuse pool*, never live inference memory, so it cannot truncate or fail a transcription, and max single-session capacity (448 output tokens / 30 s audio window) is unchanged. **Do NOT add a per-dictation `clearCache()`** - it would discard reusable fixed-shape buffers (per-token decode tensors) for no benefit; the launch-time cap is the surgical fix. The value mirrors `LiveCaptionTuning.mlxCacheLimitMB` (1024). | `Sources/HushType/AppDelegate.swift` (launch set), `Sources/HushType/LiveCaptionManager.swift:138` (value mirror) |
| Translation uses explicit source language | Auto-detect (`source: nil`) in TranslationSession.Configuration causes `unableToIdentifyLanguage`. NLLanguageRecognizer detects the real language; LanguageAvailability validates the pair before calling translate. Unsupported/missing languages get typed error alerts. | `Sources/HushType/TranslationManager.swift` |

A hidden 1x1 NSWindow with NSHostingView hosts the bridge. Window must be `orderFront` (not off-screen) for `.onAppear` to fire. | `Sources/HushType/TranslationManager.swift` |
| Live Caption session state is never restored on launch | Always-on audio capture must require explicit user action each session. `liveCaptionEnabled` is session-only and defaults false on every launch. Last-used mode/source can persist only as a convenience for the Right Cmd + `/` toggle after the user starts a session. | `Sources/HushType/AppConfig.swift`, `Sources/HushType/AppDelegate.swift` |
| Live Caption and Live Translated Caption share one panel but different trust models | Local Live Caption uses the on-device Qwen3-ASR backend and can run from mic or system audio. Live Translated Caption is an explicit opt-in cloud path: user-provided OpenAI key, one-time disclosure, session cost chip, auto-stop/daily-cap guardrails, and no HushType server in the middle. Keep UI copy clear about the mode currently running. | `Sources/HushType/LiveCaptionManager.swift`, `Sources/HushType/LocalQwen3Backend.swift`, `Sources/HushType/OpenAITranslateBackend.swift`, `Sources/HushType/CloudOnboardingAlert.swift` |

## Vision & North Star

HushType is the **fastest local-first voice-to-text tool for macOS power users**: local by default, no subscription, low latency, with explicit opt-in cloud dictation and translated captions only when the user supplies their own provider key. The product thesis: on-device ML has crossed the quality threshold for daily-driver voice input, and Apple Silicon is the right platform to prove it.

**Target user:** Bilingual (EN/ZH) knowledge workers who type all day and want voice as a faster input modality without sending audio to a server.

**Differentiators:** Local dictation and local captions (Qwen3-ASR on Metal), Traditional Chinese output (OpenCC s2twp), deterministic ITN, on-device Text Polish proofreading with a track-changes result card (Apple FoundationModels, macOS 26+), instant selected-text translation (Apple Translation Framework), opt-in cloud dictation (OpenAI / Gemini, own-key HTTPS direct, consent + daily-cap guardrails, ~0 model RAM), opt-in live translated captions via user's own OpenAI key, single-key activation (Right ⌥), fully offline by default after first model download.

## Workstreams

Development is organized into two workstreams with separate planning documents:

| Workstream | Owner | Location | Scope |
|---|---|---|---|
| **Product Development** | Product agent | `Product_WS/` (folder) | Feature backlog, technical debt, architecture, testing, releases |

The two workstreams use slightly different layouts:

Both layouts are local-only (gitignored). Read the respective workstream doc for prioritized backlog and active work. CLAUDE.md is the **shared reference** - stable facts about what exists and how the system works. Workstream docs are **living workspaces** - what to build/ship next.

## Conventions

- **Version**: semver in `Resources/Info.plist` (`CFBundleShortVersionString`). Tag format: `v0.2.1`.
- **Branching**: use a scoped `<type>/<slug>` branch (`feature/`, `fix/`, `docs/`, or the active agent's required prefix), then squash-merge the PR before any release tag.
- **DMG is gitignored**: `*.dmg` in `.gitignore`. Only lives on GitHub Releases.

## Release SOP (validated end-to-end on v0.5.11, 2026-08-24)

Run in order; every step has Felix's standing approval once he says "release".

1. **Docs final.** Release-note draft at `Product_WS/RELEASE_NOTES_vX.Y.Z_draft.md` (becomes the GitHub Release body verbatim, minus the draft header). Bilingual, 繁體中文 on top. README.md + README.en.md updated in the same batch and consistent with each other.
2. **No long dashes** (Felix house rule): scan `README.md`, `README.en.md`, and the release-note body for U+2014/U+2013 and fix them (box-drawing U+2500 in diagrams is fine). Each shipped document must report `0 0`.
3. **Gate green** on the release branch: `swift build -c release --disable-sandbox` · `swift test --disable-sandbox` · `bash scripts/check_localizations.sh --source-manifest .build/l10n_source_manifest.json` · key-egress grep (`rg -n '\?key=|allHTTPHeaderFields' Sources/HushType` → empty).
4. **Merge → tag**: merge branch to `main`, push, then `git tag -a vX.Y.Z -m "..."` + push tag. Bump `CFBundleShortVersionString`/`CFBundleVersion` in `Resources/Info.plist` BEFORE this point.
5. **DMG**: `make dmg` (bundles OpenCC, signs, runs the in-bundle localization check). Verify `codesign --verify --deep --strict HushType.app`.
6. **GitHub Release**: `gh` CLI has a TLS fault (OSStatus -26276), and its stored token may be stale even when Git push authentication works. Use curl with a token from `gh auth token` when valid, otherwise retrieve the existing HTTPS credential with `git credential fill`; validate it against `https://api.github.com/user` without printing or persisting it. POST `https://api.github.com/repos/felixfu824/HushType/releases` (tag_name/name/body JSON), then upload the DMG to `https://uploads.github.com/.../releases/<id>/assets?name=HushType.dmg` with `Content-Type: application/x-apple-diskimage`. Never echo the token.
7. **⚠️ Sync the microsite** (easy to forget - byfkc.com/hushtype renders a VENDORED copy of README.md): in `~/Developer/09_Dev/byfkc-site`, run `node scripts/sync-readmes.mjs` → `bun run build` → commit `src/readmes/hushtype.md` → push (Cloudflare auto-deploys). Do this after EVERY README change, not just releases. ⚠️ sync-readmes only refreshes the README body; the page's HERO copy (tagline / intro / meta / JSON-LD in `src/pages/hushtype.astro`) and the homepage card (`index.astro`) are hard-coded: review them whenever positioning or the feature set changes (missed on v0.5.10, caught by Felix).
8. **Verify and install the public artifact**: download the DMG again from the published GitHub asset, compare its SHA-256 with the locally built DMG, and attach the downloaded copy read-only. Verify the mounted app signature. Stop HushType, move the exact old `/Applications/HushType.app` into a `mktemp -d` backup, then `ditto` the mounted app into `/Applications` so no stale bundle files survive. Verify the installed signature and require the mounted/installed executable hashes to match. Detach, delete the temporary backup only after success, and launch the installed app. Ad-hoc signing may require permission repair.
9. **Close the books**: mark the Product_WS release-note draft SHIPPED, update the relevant `Product_WS/BUILD_STATUS_*.md`, and add the version entry to Recently Shipped above.
- **Transient handoffs**: keep task-specific handoffs inside the local Product/GtM workstreams and archive them when shipped. Do not create a third root-level source of truth.
- **Co-author**: Every commit must credit the agent models that materially authored its changes. Use the exact trailer established for the active task; do not guess a "current" model from historical commits.
